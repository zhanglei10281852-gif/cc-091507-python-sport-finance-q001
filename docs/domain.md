# 领域说明

赞助合同通常按里程碑分期付款，训练营、差旅和税费预留会消耗赛季预算。合同生效日、验收日、银行价值日和更正时间可能不同，记录需要同时保留业务发生顺序与接收顺序。金额精度、币种、退款和冻结余额属于长期留存的账本信息。

`reference/domain.json` 保存公开的合同事件、资金用途和币种枚举。正式流水应使用稳定标识，并区分业务时间、接收时间和版本。

## 事件溯源与确认期间

账本只追加、不修改：所有事实写入 `.runtime/events.jsonl`，状态由事件流重放得到。每个事件携带：

- `business_date`：业务发生日（合同生效日、验收日、银行价值日）；
- `received_at`：系统接收时间；
- `period`：确认期间（YYYY-MM）。取业务月份，若该月快照已对外报出则顺延到第一个未报出的月份；且不早于其依赖对象（合同登记、被关联流水）的确认期间，保证任意按期间截取的事件子集因果闭合、可安全重放。

因此迟到的验收回执、补录的票据只会影响尚未报出的月份，已发布的月度快照保持原样，且可按快照记录的 `basis`（水位线 + 事件摘要）复算。

## 合同变更

`contract_amended` 从生效日起重写分期计划：生效日及之后、仍未验收的分期按新清单替换，清单未覆盖的视为取消；生效日之前或已验收/已取消的分期一律不动。每次变更在合同上留下版本历史（`versions`）。

## 关联流水

退款（`refund`）、冲正（`reversal`）与汇率差额（`fx_adjustment`）通过 `links_to` 指向原始流水：退款部分冲减（不超过可退余额），冲正全额抵消并回滚分期已付金额，汇率差额计入独立的 `fx_difference` 桶并进入可支配余额。同一银行回单（`receipt_no`）重传幂等，不重复入账。
